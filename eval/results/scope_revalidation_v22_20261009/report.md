# 版解決後の回答再検証：不具合対応結果

2026年10月9日。対象 `scope-classification-v2.2-candidate`。本番未適用。

## 対応した問題

前候補は版競合を解決した後、生成回答を再検証せず「根拠十分」に昇格できた。前回のv2.1はこれを一律安全停止にしたが、正しい回答も停止していた。v2.2では版解決後に分類器を1回だけ呼び、変更しない生成回答を元質問・取得根拠全文に照らして再検証する。

- 元の対象、intent、claim-ID対応を維持させ、対象変更を検出したら停止。
- 支持・充足の両方を満たす回答だけ表示。未解消の版競合、低confidence、不正参照、schema/API失敗もラベルなし・claim非表示。
- 版以外の個別事情・裁量の確認事項は元の理由と根拠をコードでも保持する。
- Resolverの結果は検証対象の観測として渡し、根拠本文を省略しない。
- Resolverと再検証それぞれの生出力、採用した出力、confidence、判断根拠、token、エラーを同じrequest IDで監査できる。
- 生成失敗時の返却メタデータに残っていた旧候補名も現行の版番号へ統一した。

通常の経路に追加callはない。版解消時は分類器への追加callが1回増える。生成し直しやアプリ側の再試行は行わない。LLMが再検証でも誤判定する可能性は残るため、決定的な意味保証とは扱わない。

## 検証

関連ローカルテストは **85 passed**。正常回復、支持・充足不足、対象変更、claim変更、版判定不一致、低confidence、不正参照、schema/API失敗、個別事実・裁量の保持、画面の安全表示を含む。Ruffとgit diff --checkも通過。

新規APIは同一モデル `gemini-3.1-flash-lite` の **4回**。既知の不具合に対する再検証部分だけを実行し、初段の分類と版解決の出力は固定した。検索・生成を含む全経路のLLM評価ではない。条件とソースhashは[manifest](manifest.json)、詳細は[results](results.json)に保存した。各requestファイルに実際のprompt・schemaを保存し、期待ラベルをモデル入力に含めていない。

| 条件 | 結果 |
|---|---|
| 根拠に一致する2027年の300円回答 | 根拠十分で表示 |
| 解消済みの競合を理由に単価を答えない回答 | GENERATION_INCOMPLETE、主張非表示 |
| 古い版の200円を答える回答 | GENERATION_INCOMPLETE、主張非表示 |
| 300円の規則は分かるが個別記録は未照合 | 判断要、確認事項を表示 |

4条件すべて最終表示の期待に一致。内部factorすべてが正解という意味ではない。未確定回答と古い単価の2例では、LLMが生成回答の誤りを `case_fact` にも分類した。コードは主張支持・回答充足の不備を先に検出して非表示にしたため危険な表示には至らなかったが、確認理由の型の意味精度は後続評価の残課題とする。単なるschemaエラーやAPI失敗は今回の成功に数えていない。

管理費用は0.015298 USD（上限0.40）。入力1/出力10 USD/百万tokenの予算管理仮定であり請求額ではない。再試行・モデル切替なし。4例は開発用の既知機構確認であり、汎化成功率・全分類精度・ホールドアウト成功率とは呼ばない。

## 残る本番受入条件

独立レビューで発見した誤昇格と監査不足へのコード対応を完了した。修正版全体の既知入力比較、独立challenge、既存130問と100表現の新規回帰、運用評価、fresh sealed holdoutは別途必要。以前のストレージ統合3件の接続失敗は今回再実行しておらず、合格へ更新しない。本番設定とデプロイは変更していない。
