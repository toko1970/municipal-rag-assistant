# 個別結論ゲート・プロンプト候補3の開発評価（2026-10-20）

## 結果

質問内で確認できる事実と文書上の要件がそろう場合に限って個別結論を許可し、どちらかが不足する場合には可否を確定しない候補3（`conclusion_gate_v3`）を評価した。候補1・2とは異なり、A2では結論の肯定・否定を避けること、分類を「判断要」とした回答本文に個別断定を含めないこと、一般的な制度説明と個別結論を分けることを明記した。

固定文脈を使った20件の開発評価では、A1対照10件はすべて根拠に沿って直接回答し、不要な保留は観察されなかった。A2ケースでは、Q211の回答本文は一律に判断できないと説明したものの、分類を「根拠十分」としており、承認済み期待区分「判断要」と一致しなかった。Q391は回答が途中で切れた。ほかのA2回答は、個別条件の確認を促すか制度上の不確定性を説明した。

一方、A2のQ391は出力が1,020 tokensで上限に達し、根拠文書の説明途中で切れている。X041-T1では分類を「判断要」とし、承認状況と勤務実績が未確認であること、個別の可否を確定できないこと、確認先を示した。ただし冒頭に一般要件を説明する文があり、質問者のケースへの断定と誤読されないかは実務者確認を要する。従って、X041-T1を確実に解消したとは判定しない。

この小規模runは候補3の不採用または採用を決める正式なM1〜M4評価ではない。Q391の回答完了性に明確な失敗があり、X041-T1も人手判定が未了のため、**候補3は未採用とし、既定動作へ反映しない**。ここでの所見は今後の候補設計に使う開発結果であり、ホールドアウト精度ではない。

## 次の判断

候補3は既定値にしない。Q391の長い文書間不一致ケースで回答が切れた原因を、文面の長さと出力上限を含めて分析する。X041-T1の冒頭文が個別結論と誤読されないかは、実務者に回答本文を確認してもらう。これらを見た後の候補調整結果は開発データであり、最終採用には候補を固定してから新たに用意する独立のsealed holdoutが必要である。
