# 個別結論の条件照合プロンプト候補評価（2026-10-20）

## 結果

回答前に質問内の事実と根拠文書上の必須条件を照合する、汎用プロンプト候補を2種類比較した。どちらも重視ケースX041-T1の「未確認条件があるのに個別結論を断定する」失敗を止められなかった。**両候補とも不採用とし、既定動作へ反映しない。**

候補1は条件照合に加えて確認事項の列挙を促した。X041-T0では承認状況が未確認だと説明して結論を保留したが、X041-T1では「支給対象」と先に述べ、その直後の条件説明が出力上限で途中終了した。Q281も質問に記載済みの出生月と扶養認定を踏まえず、判断を保留する回答が途中終了した。

候補2は、未確認条件があれば冒頭で個別結論を確定できないと伝え、条件付き制度説明と個別結論を分ける指示を明確にし、回答を簡潔にする指示を加えた。X041-T0の回答は未確定を先に示したが、X041-T1は「根拠十分」と分類し、「時間外勤務手当の支給対象となります」と述べてから承認条件を付けた。これは、A2の回答で結論を断定した後に確認事項を足しても成功扱いしない評価仕様に照らして失敗である。Q281も個別結論を保留し、質問にある情報だけで答えられるケースへの不要保留を解消できなかった。

したがって、条件確認の指示を増やすだけでは、冒頭の結論と後段の留保が矛盾する回答を防げず、回答可能ケースの過剰保留も抑えられなかった。X035-T2とQ281は候補2でも最大1,020出力tokenで終了しており、回答の完了性にも問題が残る。

## 実行条件とデータの位置付け

- モデルはgemini-3.8-flash、temperature 0、最大出力1,024 tokens、各ケース1回、再試行なし。
- 保存済みの同一質問・検索文脈を使ったcontext-fixed評価。追加検索・Embedding API呼び出しはない。
- 候補1は回答保留用development 46件と対照Q281・Q386の計48件。候補2は回答保留用developmentの重点ケースと回答可能対照の計18件。
- いずれも開発用データであり、ホールドアウト結果ではない。回答保留development 46件は従来のE2E評価ですでに使われているため、未使用データとは扱わない。
- モデル選定実験で開封済みの予約テスト44件は使っていない。
- Q386は回答可能性A1の実務者承認がある一方、分類期待値は「判断要」のままという既知の不整合がある。回答本文はA1の承認解釈で確認し、古い分類期待値との不一致を回答品質の失敗には数えない。
- 旧回答保留用JSONのラベルと、後の実務者承認済みレビューで差がある。特に候補2の対象には、後のレビューでA1へ見直されたケースが5件含まれる。正式な指標集計では必ずpractitioner_review.csvの承認済み判断を使い、元JSONのA2/A3数をそのまま分母にしない。
- Streamlit画面は通していない。検索・生成関数の画面表示、参照表示、エラー表示を評価したものではない。
- 66件すべてAPI成功。ここでの品質所見は保存回答本文の予備分析で、実務者承認済み採点ではない。正式なM1〜M4集計にはしない。
