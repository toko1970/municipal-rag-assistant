# 図表RAGの実装状況

## 結論

現状は、**レビュー済みの架空PDF図表を取込み、検索し、元画像を確認して回答し、画面へ根拠画像を表示するvertical slice**まで実装している。任意の業務文書を画面から登録・自動公開できる汎用文書管理機能ではない。

## 実装済みの流れ

```mermaid
flowchart LR
    A["架空PDFの指定ページ"] --> B["150 dpiで画像化"]
    B --> C["Geminiが構造化JSONを生成"]
    C --> D["Schema・構造・画像hashを検証"]
    D --> E["人が内容を確認"]
    E -->|承認済みのみ| F["PostgreSQLへ構造を保存<br/>GCSへページ画像を保存"]
    F --> G["説明文をEmbedding<br/>Qdrantへ登録"]
    G --> H["質問時に図表を検索"]
    H --> I["元画像を最大3枚Geminiへ渡す"]
    I --> J["回答・分類・根拠画像を表示"]
```

| 機能 | 状態 | 内容 |
|---|---|---|
| PDFページ画像化 | 実装済み | PyMuPDFで指定ページをPNG化 |
| 図表構造化 | 実装済み | Gemini structured outputでフローチャート、表、タイムライン、帳票を抽出 |
| 検証 | 実装済み | JSON Schema、node・edge、cell、bbox、画像SHA-256を確認 |
| 人手レビューgate | 実装済み | `--reviewed`なしでは検索indexへ登録しない |
| Asset保存 | 実装済み | Localまたはprivate GCSへページ画像を保存 |
| 検索 | 実装済み | 構造JSONを文章化し、Contextual heading付きtext vectorとしてQdrantへ登録 |
| Multimodal回答 | 実装済み | 検索hitの元画像を最大3枚Geminiへ渡す |
| 根拠画像表示 | 実装済み | Streamlitの参照欄でページ画像を表示 |
| 公開デモ用データ | 実装済み | レビュー済みの架空fixture 6件をCloud bootstrapで冪等登録 |

## 実装していない範囲

- 利用者または文書管理者がWeb画面から任意のPDFをアップロードする機能
- 抽出候補を修正・承認する管理画面
- PDF全体から対象ページや図表種類を自動判定する汎用pipeline
- 任意のスキャン文書を自動OCRして無確認で公開する処理
- DOCX、PPTX、XLSXを自動でPDFへ変換する処理
- 画像Embeddingによるcross-modal検索
- 大量文書、同時アクセス、本番SLAを前提にした運用

抽出用CLIは存在するが、生成物は必ず`REVIEW_REQUIRED`として扱う。公開デモのbootstrapは、デプロイ中に任意PDFを新規抽出するのではなく、事前レビュー済みのfixture JSONを登録する。

## 評価結果

Visual sealed holdout v2では、開発に使っていないPDF 4件・質問10件を評価した。

| 指標 | 実測 | 事前閾値 | 判定 |
|---|---:|---:|---|
| 抽出Schema valid率 | 100% | 100% | 合格 |
| 回答完走率 | 100% | 100% | 合格 |
| 回答分類精度 | 70% | 80% | **不合格** |
| 必要文書取得率 | 100% | 80% | 合格 |
| 回答キー包含率 | 90% | 80% | 合格 |
| End-to-End成功率 | 70% | 70% | 合格 |

6条件中5条件を満たしたが、分類精度が事前閾値に届かなかったため、総合判定は不合格とした。必要文書は取得できており、主な弱点は、明示された図表条件から回答できる場合にもClassifierが不要な個別確認を加え、`判断要`へ寄せたことである。

詳細: [Visual sealed holdout v2受入結果](../VISUAL_HOLDOUT_V2_RESULT.md)

## ポートフォリオで説明できること

- 図表を画像のまま検索するのではなく、レビュー済み構造を検索表現に変換し、回答時は元画像も確認する構成を実装した。
- モデル出力を直接正本にせず、Schema検証、画像hash、人手レビューを登録条件にした。
- 抽出、検索、生成、分類を別々に測り、検索成功だけで図表RAGを合格にしなかった。
- Vertical sliceは公開済みだが、分類品質と文書管理UIを含む汎用運用は今後の課題である。
