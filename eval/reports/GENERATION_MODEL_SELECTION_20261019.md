## 1. 比較条件

### 比較対象と入力

比較対象は次の3モデルである。

- `gemini-3.1-flash-lite`（リポジトリの回答生成モデル既定値）
- `gemini-3.8-flash`
- `gemini-3.1-pro-preview`

モデルの効果だけを比べるため、質問文と根拠文書を固定して全モデルへ同じ入力を渡した。根拠文書は、実務経験者承認済み90問評価ブックから抽出したケースごとの提示文書であり、このモデル比較中にベクトル検索は実行していない。検索結果の差を回答生成モデルの差へ混ぜないためのcontext-fixed評価である。

### 回答生成までの経路

```text
評価ケースの質問文 + 固定済み根拠文書
              ↓
既存の自然文プロンプト（src.rag_chain.build_prompt）
              ↓
対象モデルを1回呼び出し
              ↓
「回答分類・回答・根拠文書」を含むテキスト出力
```

質問意図の事前構造化、根拠文書の要素解析、v1の回答JSON Schema、独立した分類器による後段判定は使用していない。モデルは回答本文と分類ラベルを同じ呼び出しで生成し、評価ではその出力本文を採点した。したがって、ここでの自動分類ラベル一致率は補助指標であり、本番の独立分類器の性能を示すものではない。

### 固定した実行条件

| 条件 | 内容 |
|---|---|
| Provider | Gemini Developer API |
| Temperature | 0 |
| 最大出力 | 1,024 tokens |
| 試行 | 1ケース・1モデルあたり1回。test確認時の再試行なし |
| prompt | `src.rag_chain.build_prompt`、全候補で同一 |
| 採点 | 承認済み評価ブックの基準に沿った回答本文の手動採点 |
| goldの扱い | 質問・根拠と期待判定を分離し、モデル応答取得後に採点へ使用 |

## 2. 比較した指標

主指標は、回答可能なA1ケースでは根拠付き回答成功（M3）、保留対象のA2/A3ケースでは適切な保留対応成功（M4）を満たした件数を合算した総合回答成功率である。

誤りの性質を分けるため、次の指標も比較した。

- M1: 保留対象に対する不適切な回答
- M2: 回答可能ケースに対する不要な保留
- G1: 重大誤り
- Q1〜Q4: 回答／保留判断、理由、次の対応、回答内容と根拠の観点
- 自動生成された回答分類ラベルの一致率（補助指標）
- REVIEW_REQUIRED、APIエラー
- API費用推定、平均応答時間、p95応答時間
- scenario group単位のペア比較

分類ラベルの一致率だけで回答品質を代表させず、回答本文を主に評価した。

ユーザーのレビューに基づき、Flashの次の3ケースを成功として再採点した。

| ケース | 反映したレビュー | 再採点 |
|---|---|---|
| X014-T0 | DOC-002の通勤条件はすべて満たす必要があり、通勤手段の記載がないためFlashの確認保留を誤答とは言えない | Flashの成功として加算。不要保留M2から除外 |
| X014-T1 | Flashも不足情報の確認を促しており、次対応を不適切とは言えない | Flashの適切な保留対応M4として加算 |
| X026-T0 | 質問は契約名義の原則を尋ねており、Flashは原則を過不足なく回答している | Flashの根拠付き回答成功M3として加算 |

この再採点でFlashの総合成功は初回32件から35件へ、成功scenario groupは13群から14群へ変わった。Flash-Lite側の件数は変更していない。X014-T0についてDOC-002の条件を完全に満たすかを厳密に問う場合、Flash-Lite回答の通勤手段条件への言及不足も別途レビュー対象となるため、ここではユーザーの指示どおりFlash側の評価だけを変更した。

再採点後もFlash-Liteの総合成功はFlashより2件多く、費用は約10.8倍低く、平均応答時間は約5.5倍短い。一方、Flashは保留対象への不適切な回答が1件少なく、G1も初回採点では1件少なかった。scenario group単位ではFlashが14/22、Flash-Liteが15/22で成功した。

## 4. 当時の採用モデルと選定理由

**採用モデルを`gemini-3.8-flash`とする。**ユーザーレビュー反映後、Flash-Liteの総合回答成功は37/44、Flashは35/44で、Flash-Liteが2件上回る。Flash-Liteは費用と応答時間でも優位であり、Flashを選ぶ理由は総合成功率や運用効率ではない。ユーザーが安全性を優先する方針を選び、再採点後もFlashは保留対象への不適切な回答が1件少なく、初回採点のG1も1件少なかったこと、開発用分割でも危険な断定の少なさが観測されたことを重視した選定である。

この選定は、評価セット上でFlashが全体として高精度、または安全性が十分であることを意味しない。総合成功数の減少、費用・応答時間の増加、および両モデルに共通するG1事例が残る。モデル選定とアプリ設定変更は別であり、この記録作成によって`LLM_MODEL_NAME`は変更していない。

### レビュー上の留意点

上表のFlash値は、回答本文を一回手動レビューした初回採点を、上記3ケースについてユーザーの指摘に基づいて再採点した値である。元のAPI応答・初回採点記録は監査用の評価artifactに維持し、変更していない。自動回答ラベル一致率は初回goldに対する参考値のままで、今回の手動再採点へ連動していない。

X026-T3はFlashとFlash-Lite双方でG1ありとされたが、質問・提示根拠が「原則」を尋ねている点に曖昧さが残る。本書ではこのG1件数を変更せず、初回採点値として扱う。独立した再レビューは未実施である。

今回開封した44件のテスト分割は、今後の候補調整や新しいモデル選定には再利用しない。将来の変更確認には別の未使用データを用いる。
