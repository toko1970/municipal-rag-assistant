# Text sealed holdout 受入評価

## 結論

固定済み候補を、開発評価とは分離した50シナリオ・100表現で評価した。総合回答成功は
83/100（83.0%）、シナリオ単位で両表現に成功した割合は39/50（78.0%）だった。検索は
document・evidenceとも100/100だった一方、回答分類は86/100で、今回の最大失敗要因だった。

## 評価条件

- candidate source commit: `5d1ecc50985db681cfa71bddc6cbfcfa99480e40`
- prediction run: `text-holdout-v1-20260929T084927Z`
- prediction SHA-256: `4d39ffabc578446073013d8b969dfaae40f498de5060024a036f4e32f3eff0c3`
- 50 scenarios / 100 expressions（formal 50、paraphrase or noisy 50）
- Gemini 3.1 Flash-Lite、gemini-embedding-001、Qdrant in-memory、Top-K 8
- 100 predictionsを固定してからgoldを開封した
- provider 503だけに最大2回の指数バックオフを許し、候補pipeline失敗は再実行しなかった
- 累計232 logical external calls、推定US$0.144191

## 失敗原因

| 原因 | 件数 | 単独失敗 | 他原因との重複 |
| --- | ---: | ---: | ---: |
| 回答分類 | 14 | 11 | 3 |
| 回答内容 | 6 | 3 | 3 |
| 実行 | 2 | 0 | 2 |
| document retrieval | 0 | 0 | 0 |

分類の混同行列では、`根拠十分 → 判断要`が9件、`判断要 → 根拠十分`が3件だった。残り2件は
候補pipelineが回答を組み立てられず、分類結果も作れなかった。主な傾向は、正しい金額や期限を回答
できているにもかかわらず、不要な「個別事情の確認」を付けて`判断要`へ寄せる過剰慎重である。

内容失敗6件の内訳は次のとおり。

- TH011の2表現: 金額は正しいが、提出期限を`2027年10月30日正午`まで算出せず起算規則だけを回答
- TH039の2表現: 休務時間は正しいが、申込期限を`2027年6月15日17時`まで算出せず起算規則だけを回答
- TH014 formal、TH026 paraphrase: 候補pipelineの表示条件不整合により回答本文を生成できなかった

言い換えによる大幅な低下はなかった。単一文書の直接質問は全件成功し、複数文書と版境界の質問で
失敗が集中した。ただし検索は全件成功しているため、このholdoutでは検索改善より、分類の校正と
具体的な期限計算を優先する根拠がある。

## 開発評価との関係

開発評価は120/130（92.3%）、sealed holdoutは83/100（83.0%）だった。質問集合が異なるため、
9.3ポイント差をそのまま性能退行とは扱わない。開発中に見えていなかった複数文書・版境界での
分類校正と、具体日への計算不足が未知データで顕在化した結果として扱う。

## 内容reviewの基準と限界

内容は文字列一致ではなく、質問で直接求められた金額、期限、可否がgoldの期待要点と意味上一致するかを
確認した。判断要の質問では、可否と追加確認事項を正しく示していれば、goldに記載された補足的な金額を
すべて列挙していなくても成功とした。一方、具体的な期限を求める質問で起算規則だけを示した回答は
不合格とした。この初回reviewはCodexが実施しており、面接資料へ最終掲載する前にレビュー記録を目視確認
できるよう、各表現の判定理由を`content_review.jsonl`へ保存している。
