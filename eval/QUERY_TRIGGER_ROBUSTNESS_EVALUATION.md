# Query trigger robustness evaluation

## 目的

Query Decompositionと生成前版注記について、既知質問の改善と未知表現への汎化を分けて評価する。
質問IDやgold evidenceを実行時に参照する例外処理は導入しない。

## 評価設計

- 実装変更前に、言い換え、境界例、制度違い、非対象質問を含む40件を固定した。
- 40件は改善用development setであり、sealed holdoutではない。
- 外部APIを使わず、分解規則と時点補足の発火だけを決定的に比較した。
- 改善後は、既存の固定500問全体に対する誤発火と取りこぼしも監査した。
- 検索結果と最終回答の品質は、この評価だけでは合格としない。

## 結果

| 指標 | 変更前 | 候補 |
|---|---:|---:|
| 分解トリガー適合率 | 80.0% | 100.0% |
| 分解トリガー再現率 | 25.0% | 100.0% |
| 時点補足適合率 | 100.0% | 100.0% |
| 時点補足再現率 | 70.0% | 100.0% |

変更前は分解で12件、時点補足で3件を取りこぼし、分解で1件を誤発火した。候補は40件の
全ラベルに一致した。候補では、文字列の完全一致を増やすのではなく、出来事、通勤実態消失、
支給開始、提出期限を別々の概念群として判定する。転居の否定表現は分解対象外にした。

既存500問のcorpus監査では、対象3シナリオ15問中13問で発火し、対象外への誤発火は0件だった。
適合率は100%、再現率は86.7%である。`Q160`と`Q440`の「つうきん」という表記揺れは
取りこぼした。この2件を後からdevelopment setへ混ぜて100%へ見せかけず、残る限界として保持する。

## 判断と限界

トリガー層の候補としては採用する。ただし、40件は改善にも使ったため、ここでの100%は汎化性能の
証明ではない。500問監査も同一scenarioの定型的なvariantが中心で、意味の多様性は限定される。

本番適用gateには、次の二段階が残る。

1. 新しい言い換えについて、検索根拠が改善し非対象質問が退行しないことを確認する。
2. 検索を通過した候補について、回答内容、根拠支持、分類を含む総合回答成功を確認する。

最終採用では、別に固定した未使用セットまたはsealed holdoutを使う。sealed holdoutの開封とgold採点は
別の承認境界とする。
