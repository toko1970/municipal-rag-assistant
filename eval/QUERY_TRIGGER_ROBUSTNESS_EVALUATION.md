# Query trigger robustness evaluation

## 目的

Query Decompositionと生成前版注記について、既知質問の改善と未知表現への汎化を分けて評価する。
質問IDやgold evidenceを実行時に参照する例外処理は導入しない。

## 評価設計

- 実装変更前に、言い換え、境界例、制度違い、非対象質問を含む40件を固定した。
- 40件は改善用development setであり、sealed holdoutではない。
- 外部APIを使わず、分解規則と時点補足の発火だけを決定的に比較した。
- 改善後は、既存の固定500問全体に対する誤発火と取りこぼしも監査した。
- 検索結果と最終回答の品質は、この評価だけでは合格としない。

## 結果

| 指標 | 変更前 | 候補 |
|---|---:|---:|
| 分解トリガー適合率 | 80.0% | 100.0% |
| 分解トリガー再現率 | 25.0% | 100.0% |
| 時点補足適合率 | 100.0% | 100.0% |
| 時点補足再現率 | 70.0% | 100.0% |

変更前は分解で12件、時点補足で3件を取りこぼし、分解で1件を誤発火した。候補は40件の
全ラベルに一致した。候補では、文字列の完全一致を増やすのではなく、出来事、通勤実態消失、
支給開始、提出期限を別々の概念群として判定する。転居の否定表現は分解対象外にした。

既存500問のcorpus監査では、対象3シナリオ15問中13問で発火し、対象外への誤発火は0件だった。
適合率は100%、再現率は86.7%である。`Q160`と`Q440`の「つうきん」という表記揺れは
取りこぼした。この2件を後からdevelopment setへ混ぜて100%へ見せかけず、残る限界として保持する。

## 判断と限界

トリガー層の候補としては採用する。ただし、40件は改善にも使ったため、ここでの100%は汎化性能の
証明ではない。500問監査も同一scenarioの定型的なvariantが中心で、意味の多様性は限定される。

本番適用gateには、次の二段階が残る。

1. 新しい言い換えについて、検索根拠が改善し非対象質問が退行しないことを確認する。
2. 検索を通過した候補について、回答内容、根拠支持、分類を含む総合回答成功を確認する。

最終採用では、別に固定した未使用セットまたはsealed holdoutを使う。sealed holdoutの開封とgold採点は
別の承認境界とする。

## 検索比較

未知表現の肯定例16件について、同じEmbedding、文書cache、Top 8でDense検索と分解検索を比較した。
最初の候補は成功4件から9件へ改善したが、subqueryだけで8枠を使い切り、元質問が取得していた
経過措置を失う退行が3件あった。

質問別例外は追加せず、Top 8の半分をsubquery、残りを元質問へ予約した。再評価では成功が
4/16から13/16へ改善し、退行は0件になったため検索gateを通過した。Embeddingは初回1 logical call、
再評価はcache利用で0 call、retry 0、費用上限US$0.001だった。

## 回答比較

回答条件を定義した9件をbaselineと候補で比較した。最初のrunは8/18シナリオ終了時にGemini
free tierの1分あたり15 request上限で429となり、fail-fastした。このrunは採否に使っていない。

シナリオ開始間隔を15秒に固定し、新しい出力先で全18シナリオを最初から測定した。待機は429後の
retryではなく、事前の負荷制御である。

| 指標 | baseline | 候補 |
|---|---:|---:|
| 総合成功 | 1/9 | 3/9 |
| 改善 | - | 3件 (`G01`, `G04`, `G09`) |
| 退行 | - | 1件 (`G07`) |

- 完了: 18/18シナリオ
- 使用: 36 logical calls、推定US$0.019009
- provider error: 0
- retry: 0
- 判定: 退行1件のためgate不合格

`G07`は両方式とも検索に成功した。baselineと候補の生成claimsはいずれも、通勤実態消失時の停止と
住所変更届の14日以内提出を根拠付きで生成した。一方、候補だけが「通勤手当を止める具体的な時期は
資料にない」をmissing conditionへ追加し、分類器が文書不足と判定した。検索退行ではなく、
「通勤実態消失時に停止」という規定で時期へ十分答えられるかというanswerability判定の差である。

診断再測定でもbaseline成功・候補失敗が再現した。評価後に正解条件を変更せず、現在の候補は
本番適用gateを通過していないものとして保持する。

### 最初の中断run

- 中断時点: baseline成功0、候補成功1、改善1、退行0
