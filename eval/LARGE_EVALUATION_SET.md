# 500問評価セットの設計

給与事務担当者が職員から問い合わせを受け、制度文書を確認する場面を想定して、100個のシナリオと5種類の表現から500問を作成した。

## ファイル

- 評価質問: [evaluation_questions_500.csv](evaluation_questions_500.csv)
- 再生成: `python -m eval.generate_large_evaluation_set`
- 構造・根拠検証: `python -m eval.validate_large_evaluation_set`

## 500問の構造

各シナリオに次の5表現を用意している。

| 表現 | 目的 | 件数 |
| --- | --- | ---: |
| formal | 制度上の論点を明示した標準表現 | 100 |
| staff_consultation | 職員から相談を受けた所属担当者の表現 | 100 |
| concise | 給与事務担当者が短く確認する表現 | 100 |
| colloquial | 「給料」「通勤ルート」などの言い換え | 100 |
| noisy | 誤字、ひらがな、表記揺れを含む表現 | 100 |

同じシナリオの5問は、質問表現だけが異なり、正解文書、正解見出し、回答分類、回答要点は共通である。このため、単純な500問正解率だけでなく、表現変化に対する安定性を測定できる。

## 回答分類

| 期待分類 | 件数 | 割合 |
| --- | ---: | ---: |
| 根拠十分 | 365 | 73% |
| 判断要 | 75 | 15% |
| 文書不足 | 60 | 12% |

文書不足の質問には正解文書・正解見出しを設定していない。これらを検索失敗の分母へ含めず、回答分類と幻覚抑制で評価する。

## 主な分野

給与支給日、給与計算、給与明細、控除、給与口座、過払返納、通勤手当、住居手当、扶養手当、時間外勤務手当、住所変更、届出手続き、システム入力、制度改正、複数文書をまたぐ手続きを含む。

文書に答えがない質問には、退職手当、育児休業、テレワーク手当、副業、賞与、共済扶養、年末調整、産前産後休暇、管理職手当、単身赴任手当を含めた。

## 評価の段階

### 1. 開発時の短時間確認

既存のテストと少数の固定質問を使う。コード変更ごとにAPIを500回呼ばない。

### 2. モデル比較・改善候補の選別

`variant_type=formal`の100問を使う。100シナリオを一度ずつ評価するため、特定の言い換えが結果を過度に左右しない。

### 3. 最終評価

候補を絞った後、500問すべてを実行する。次の単位で集計する。

- 500問全体の正解率
- 100シナリオのマクロ平均
- 表現5種類ごとの成績
- 分野ごとの成績
- 根拠十分・判断要・文書不足ごとの成績
- 検索、回答生成、回答分類、文書不足対応の失敗割合

## 正解データ

各行には次を保存している。

- `expected_document_ids`: 回答に必要な文書
- `expected_evidence`: 文書IDと完全な見出しパス
- `expected_answer_type`: 根拠十分、判断要、文書不足
- `expected_answer_key`: 回答に含めるべき要点
- `scenario_id`: 同じ意味を持つ5表現のグループ
- `variant_type`: 表現の種類

`validate_large_evaluation_set.py`は、質問数、重複、シナリオごとの表現数、回答分類、文書IDと見出しの実在を検証する。

## 利用前の確認

現在の`review_status`は全件`assistant_draft`である。自動検証では、質問の業務上の自然さや正解要点の解釈までは保証できない。最初の本評価前に、100個のformal質問と正解要点を人が確認し、同じシナリオの5表現に意味のずれがないことを確認する。

評価結果を見て質問を削除・変更すると指標が恣意的になるため、レビュー完了後はバージョンを固定する。修正する場合は理由と変更前後を記録する。
