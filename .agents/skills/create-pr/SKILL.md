# create-pr

1. `AGENTS.md`、該当するルール、`docs/rules/review.md`を読む。差分と作業の根拠となった仕様・計画・AIレビュー結果を確認する。base branchは推測せず実際のbranch/remoteを確認する。
2. 本文を次の順で下書きする。
   - 課題: 目的、背景、関連issue/計画。
   - 解決: 変更点、主要な設計判断とトレードオフ。
   - 検証: 実行したtest/evalコマンドと結果、未実施・制約。
   - レビュー観点: 影響範囲、特に見てほしい箇所、残課題。
3. プロジェクトが使うPR下書き置場が確認できればそこへ保存する。未作成なら投稿前の本文を提示する。
4. 投稿やpushはユーザーの明示依頼・承認後にだけ実行する。承認前は本文作成と差分準備まで行う。投稿後はCIとレビューの状態を区別して報告する。
