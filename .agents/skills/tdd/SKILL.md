# TDD

1. `AGENTS.md`と変更対象に該当する`docs/rules/*.md`を読む。期待動作の根拠を依頼・承認済み仕様・設計/schemaから特定し、実装コードを正解にしない。不明な前提が合否に影響する場合は推測せず、確認事項を報告する。
2. 正常系、境界の両側、欠落・不正値、失敗経路、既存回帰からテストリストを作る。未実装の全ケースを一度に書かず、最小の1ケースから始める。
3. 対象pytestを実行して、期待した振る舞いの欠落によるRedを確認する。環境/依存のエラーはRedと数えない。最初から通る場合は既存実装とassertの強度を調べる。
4. テストを通す最小の本実装を行う。固定値、testだけの分岐、assert除去、skip、無関係なmockでGreenにしない。
5. Greenを保ちながら整理し、変更ごとに関係testを実行する。失敗したら原因を調べ、既存testを弱めず修正する。
6. 影響範囲に応じてREADME記載の通常CIコマンドまたはintegration testを実行する。RAG品質候補の評価が必要なら`docs/rules/evaluation.md`に従い、通常testと混ぜない。
7. 完了報告で、テストリストの各項目、根拠、対応test、実行コマンドと結果、未確認項目を対応づける。
