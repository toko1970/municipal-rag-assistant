# 自治体の給与事務を支援する、根拠付き問い合わせアプリ

[公開デモ](https://municipal-rag-assistant-280649014820.asia-northeast1.run.app/) · [機能ごとの説明](portfolio/README.md) · [精度改善の詳しい記録](eval/reports/ACCURACY_IMPROVEMENT.md)

## どんな人が、何に使うアプリか

各所属の給与事務担当者や、人事・給与制度を所管する職員が、職員からの制度・手続きの問い合わせに答えるときに使う**調べもの支援アプリ**です。

規程、通知、FAQ、業務マニュアル、申請書の記入例を横断して探し、回答と根拠の場所を一緒に確認できます。たとえば、「給与口座を変更したいときの提出期限は？」「申請書を受け取った後、最初に何を確認する？」といった質問に使います。回答に必要な情報が見つからないときや、個別事情の判断が残るときは、その状態を示します。

制度の最終判断や申請の承認を自動化するものではありません。人事担当者が根拠を確かめ、必要に応じて所管部署へ確認するための補助です。デモでは架空の制度文書だけを使っています。

## このアプリでできること

- **質問する:** 自然な文章で給与制度や手続きについて尋ねる
- **根拠を探す:** 複数の規程・通知・FAQ・手順書に加え、図表の説明も検索する
- **根拠と回答を確認する:** 回答、文書名、版・施行日、ページや見出しを一緒に見る。図表が根拠なら元ページ画像も確認する
- **回答の状態を知る:** 「根拠十分」「判断要」「文書不足」を区別し、回答に対するfeedbackを残す

文書の登録は管理用CLIで行います。一般の利用者がPDFをアップロードして登録する画面はありません。

## アーキテクチャ

![RAGアプリのアーキテクチャ図](architecture.svg)

React画面から、FastAPIが提供する同一originのAPIを通じて、既存の質問・検索・回答処理を呼び出します。公開APIでは、匿名セッションやリクエストの重複防止、利用回数の上限によってリクエストを管理します。文書とその版、実行記録はPostgreSQLに保存し、Qdrantには必要に応じて再構築できる検索用インデックスを保存します。個人情報の自動マスキングと30日後のデータ削除は今後の対応項目で、まだ実装していません。デモには実在する個人情報や機密情報を入力しないでください。

## 精度改善の流れ

```mermaid
%%{init: {"flowchart": {"wrappingWidth": 300, "minNodeWidth": 260}}}%%
flowchart TD
    A[1. 初期版を220問で評価]
    B[2. 質問タイプごとに失敗を整理]
    C[3. 改善案を比較し退行を確認]
    D[4. 改善案を採用]
    E[5. 同じ220問で再評価<br/>回答か保留かの判断を確認]
    F[最終結果と今後<br/>統合成功率87.3%]
    A --> B --> C --> D --> E --> F
```

初期版の完成後、制度改定や個別確認、根拠不足、期限・手続などに関する質問を含む220問のセットで評価しました。質問と回答を再確認し、指摘のあった2件を正答として採点し直した結果、初期版の総合回答成功率は76.4%（168/220）となりました。

1. **失敗要因の分析:** 評価結果を失敗の種類ごとに整理し、件数が多かった失敗を改善対象にしました。220問の統合評価では、根拠不足への対応や個別審査の要否を問う質問の成功率が低く、改善が必要でした。別に行った初回Text holdout（100表現）の失敗分析では、回答分類の失敗が最も多く、とくに根拠がある質問でも不要な個別確認を求める「過剰な保留」が主な課題と分かりました。また、このRAGでは根拠のない断定を避けることも重要な目標と考え、発生件数にかかわらず、そのような失敗も改善対象に含めました。そのため、根拠や個別判断の必要性に応じた回答分類と、根拠のない断定を抑えることを改善課題に設定しました。
2. **改善実験と候補版:** 検索、回答生成、回答分類の改善案を作成し、開発用の質問で回答を評価しました。初期版で正答できていた質問に誤答するなど、既存質問への回答を損なう案は候補から外しました。残った案について、回答の正確さや網羅性、根拠の扱いを確認して候補を絞り、選定したモデル・回答経路・promptを組み合わせた版を現在の公開版として採用しました（revision `municipal-rag-assistant-00011-kwv`）。
3. **同じ220問で再評価:** 候補版の総合回答成功率は、初期版の76.4%（168/220）から87.3%（192/220）へ向上しました。回答するか保留するかの判断も、初期版の198/220問から候補版では218/220問へ改善しました。質問タイプ別では、根拠不足への対応が3/18問から13/18問、個別審査の要否の判断が14/24問から18/24問、多段階の期限・手続が16/24問から20/24問へ改善しました。
4. **今後の展望:** 今回は同じ220問で初期版からの改善を確認しましたが、未使用の質問や制度文書でも同様の改善が得られるかは、まだ分かっていません。今後は、質問の表現や制度の異なる評価ケースで改善の再現性を確かめるとともに、根拠のない断定を避けながら、根拠不足への対応や個別審査の要否判断など、失敗が残る領域の改善を目指します。

その後、採点を再確認した結果、重大誤りは初期版で3件、候補版で0件となりました。質問文・想定回答・重大誤りの基準を見直し、指定のあった計7件を正答に修正しています。元の自動judgeの出力は変更せず、質問ごとの修正内容を追補記録に残しました。

今回の比較では、モデルや回答経路など複数の変更を含むシステム版同士を比べているため、個々の変更の効果は分かりません。また、過去に固定した一部の回答を再利用しており、すべての回答を今回あらためて生成した比較ではありません。この評価はポートフォリオで改善の進め方を説明するためのもので、実際の利用環境で同じ結果になることを示すものではありません。220問の構成、固定した版、質問別スコア、費用と限界は[統合220問評価レポート](eval/results/portfolio-combined-20261115-v1/REPORT.md)に、過去の評価経緯は[評価資料の案内](eval/reports/README.md)にまとめています。
